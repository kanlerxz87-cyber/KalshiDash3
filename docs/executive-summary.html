2. How "highest dollar amount" is defined

For each open market the dashboard computes notional ≈ volume_fp × last_price_dollars (dollars traded at the last price). This is an estimate, not an official Kalshi field — Kalshi returns volume_fp and last_price_dollars separately. Source: Get Markets / live demo API. See Open Questions Q1 for the open decision on whether to use volume, open interest, or notional.

3. How resolution tracking works

Each market carries a result field: empty while open, then yes or no after settlement. The dashboard polls live markets and lists settled markets with their result. Source: Market Settlement.

4. Trading & portfolio

Public market data needs no key. Orders, balance, and positions require a signed demo API key (Ed25519 or RSA-PSS, 30-second timestamp tolerance). Source: API Keys. Because no keys were provided, this build runs a clearly-labeled paper ledger in the browser and ships a Python executor (scripts/kalshi_client.py) that trades for real on demo once keys are supplied via environment variables — never committed to the repo.

5. Rate limits & reliability

Authenticated requests cost tokens (default 10) against Read/Write budgets; unauthenticated public requests have separate limits. The dashboard polls every 5s per selected market and backs off on 429. Source: Rate Limits and Tiers.
