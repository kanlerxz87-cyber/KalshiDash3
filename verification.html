Verification — line by line

Every static claim in this project is a row below, with the official page it was checked against and the date it was checked. A value that could not be confirmed is left blank and appears on Flagged for Review. Nothing is inferred, and no row says “verified” unless the wording can be pointed at in the source.

Data quality of the committed snapshot

Directly observed from the demo API

These rows were read straight from the official demo API with the documented series_ticker + status filter, one request per series, so the query URL can be re-run by hand. This is a spot check, not a full scan: absence of a topic here proves nothing about whether it exists on the exchange. Full snapshot method is on the home page.

What “verified” means here, and what it does not

Claim typeWhat we didWhat we did not do
Endpoints, field names, enums, limits Read the official OpenAPI schema text on docs.kalshi.com and the matching guide page; copied the wording. We did not call the endpoint in this build environment for most rows, so a live 200 was not observed here.
Fees Read the published fee schedule PDF, including its “last updated and effective” date. We did not verify a fee against an actual fill, because no demo credentials exist (F-07).
Category membership Accepted only series tickers that appear verbatim in the fee schedule’s non-standard fees table. We did not infer series from naming patterns such as KXGOLF or KXGAS; those were removed.
Live prices, volumes, results Never hardcoded. Produced by scripts/collect.py and rendered with the query URL and fetch time attached. We did not type a single market number into the HTML.
Alert rule and ROI model The ≥ $0.10 swing threshold is the brief's requirement. swing_roi / high_roi is a project-local heuristic, labelled as a model wherever it is shown. We did not present the ROI score as a Kalshi-provided field; Kalshi returns no ROI field (F-15).
Cause of a jump Each alert links the official market and event API URLs. The cause is left blank and flagged. Kalshi publishes no official cause feed, so we inferred nothing and invented no news link (F-14).
