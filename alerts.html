Two scrolling chats of real-time contract-price alerts on the Kalshi demo exchange: all events and a filtered feed of events the model likes as high-ROI candidates. An alert fires whenever a watched contract moves ≥ $0.10 between two consecutive observations, up or down. The engine polls the public demo API from your browser and, when that is not possible, falls back to the collector's committed price history — every alert is labelled with its origin.

Alert threshold ($0.10, both directions): this project's stated requirement — it is not an API field. Live detection polls GET /markets?tickers=…, which returns every matching market in one response when tickers is the only filter (Get Markets). Kalshi documents that REST responses are cached briefly, so prices can lag the exchange by seconds — polling faster than that cannot add information. Unauthenticated requests have separate rate limits; the engine backs off exponentially on HTTP 429 (Rate Limits). "News leads" links are search queries, not verified causes — causality is never asserted (see F-15).

How the model pick is computed (fully disclosed)

Score = 0.30×liquidity + 0.25×price-band + 0.30×momentum + 0.15×spread, each component 0–1. Picks are alerts whose score ≥ 0.55. Components: liquidity from 24h contracts traded and the dollars-traded estimate (log-scaled); price-band peaks at 50¢ where the binary payout profile and the taker fee ceil(M×0.07×C×P×(1−P)) (fee schedule) are both maximal; momentum from the swing size (capped at 30¢); spread from the API bid/ask gap. This is a heuristic screen, not a backtested strategy and not advice — it is flagged for review (F-16).

Category tabs filter both chats. Categories stay separate — a market is attributed to one topic only, either by a fee-schedule-confirmed series (confirmed) or a flagged keyword match (keyword).
