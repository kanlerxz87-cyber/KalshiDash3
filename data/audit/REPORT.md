## Flagged for review (published on the site's Flagged for Review page)

1. **F-111 — two official sources disagree on fee multipliers.** `kalshi-fee-schedule.pdf`
   "Non-Standard Fees" lists `KXBTCY`, `KXETHY`, `KXELECTIRAN` with maker/taker multiplier
   **0**, while live `GET /series/{ticker}` returns `fee_multiplier: **1**` for the same
   series (all 39 series fetched today carry `fee_multiplier: 1`). The project's fee model
   follows the PDF (per F-84). Which source governs the effective fee is unverified —
   Kalshi exposes a "Get Series Fee Changes" endpoint and event-level fee overrides that
   may explain a base-field vs effective-multiplier distinction. Left as flagged; no value
   changed.
   Sources: https://kalshi.com/docs/kalshi-fee-schedule.pdf ·
   https://external-api.demo.kalshi.co/trade-api/v2/series/KXBTCY ·
   https://external-api.demo.kalshi.co/trade-api/v2/series/KXETHY ·
   https://external-api.demo.kalshi.co/trade-api/v2/series/KXELECTIRAN ·
   https://docs.kalshi.com/api-reference/exchange/get-series-fee-changes
2. **F-112 — `KXMAXSHARDINGTEST` is officially Crypto but looks like an exchange test
   instrument.** Official series record: `categories ["Crypto"]`, `tags ["BTC"]`, title
   **"shard"**, `frequency one_off`, contract terms `BTC.pdf`. By the project's documented
   rule (official categories decide scope; only `Test`/`Demo` are never in scope) it is
   published under Crypto. Its name suggests internal sharding test plumbing. Not excluded
   by this session (never infer) — flagged for a human decision.
   Source: https://external-api.demo.kalshi.co/trade-api/v2/series/KXMAXSHARDINGTEST
3. **F-113 — alert-cited markets outside the published size window show "not in snapshot"
   although the official API has since determined them.** Example: `KXPGATOUR-THRC26-BHAR`
   (alert row, RSM Classic) — live `GET /markets` now reports `status finalized`,
   `result "no"` (settlement 2026-11-23T19:58:03Z), but it is outside the published rows'
   size window so the site's lifecycle join reports "not in snapshot" and the outcomes
   ledger cannot count its resolution. A per-ticker resolution backfill for alert-cited
   tickers would close this gap. Left as flagged.
   Source: https://external-api.demo.kalshi.co/trade-api/v2/markets/KXPGATOUR-THRC26-BHAR
